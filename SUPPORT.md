# Support

## Current Support State

LNSAT is pre-release. Community support is best-effort until release channels,
versioned artifacts, and commercial support tiers are active.

Only current `main` source is maintained. No published version currently has a
support or security-maintenance window.

Public source remains unsupported evaluation software until an exact
version/platform/package row passes release gates. Repository access,
successful tests, or a source build does not establish production suitability
or a support contract.

## Community Support

Use public issues for:

- documentation gaps;
- build or test failures;
- bug reports without private data;
- feature requests;
- compatibility reports.

Include source revision, operating system, architecture, Node/Rust versions,
minimal reproduction, expected behavior, actual behavior, and validation output.

Do not post secrets, credentials, tokens, customer data, proprietary logs, or
private vulnerability details in public issues.

Security reports follow `SECURITY.md`; conduct reports follow
`CODE_OF_CONDUCT.md`.

## Commercial Support Direction

Future commercial support should define:

- supported versions;
- severity levels;
- response targets;
- upgrade/rollback help;
- enterprise deployment review;
- hosted-cloud incident process;
- security advisory coordination.

Private downstream repository access, documentation, or future entitlement does
not establish a support contract or action authority. Commercial terms must
name exact core/module versions, compatibility evidence, response scope, and
lifecycle separately.
